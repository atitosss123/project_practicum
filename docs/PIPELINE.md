# Пайплайн реализации: кластеризация штаммов бактерий

Задача 5 из [задания курса](task-source.docx): 20 штаммов, 7 признаков трёх разных типов,
автоматический подбор числа кластеров, визуализация.

**Что строим:** сквозной пайплайн `данные → предобработка → смешанная матрица расстояний →
иерархическая кластеризация → подбор k по силуэту → профили кластеров → визуализация`,
разложенный по модулям `src/`, с ноутбуком-обёрткой для сдачи.

Три решения, принятые до начала кодирования:

| Развилка | Решение | Почему |
|---|---|---|
| Откуда данные | Свой генератор с заложенной структурой из трёх экотипов + генератор из задания как контрольный прогон | Данные из задания — независимый `uniform` по всем признакам, то есть однородное облако без кластеров. На них метод формально работает, но находить нечего. Реальных таблиц с этими 5 признаками одновременно не существует |
| Ward на нашей матрице расстояний | Ward как основной результат (так требует задание) + average linkage как контроль | Формула Уорда предполагает евклидову метрику, а взвешенная сумма трёх расстояний ею не является. Расхождение двух разбиений — это и есть измеренная цена допущения |
| Формат сдачи | Модули `src/` + ноутбук, который их вызывает | Логика тестируема и защищаема по частям, ноутбук даёт пошаговый вывод с графиками |

---

## Данные

Реальные базы (NCBI, BacDive) дают GC-содержание и размер генома, частично — переносимость pH.
Выход продукта (`product_yield`) — биопроцессная метрика, её измеряют в своей лаборатории;
в открытых источниках по штаммам её нет. Сшивать таблицу на 20 штаммов из трёх баз — это
половина проекта на курирование данных вместо метода.

Поэтому два генератора, оба с фиксированным seed:

| Набор | Что в нём | Роль |
|---|---|---|
| [Основной](../data/strains_features.csv) | Три экотипа: кишечник — быстрый рост, низкий выход продукта, низкое GC, компактный геном; почва — медленный рост, высокий выход, щелочная переносимость, крупный геном; вода — быстрый рост и высокий выход при мелком геноме и высоком GC. Классы перекрываются | На нём считаем и интерпретируем результат |
| [Контрольный](../data/strains_uniform.csv) | Код генерации из задания, `seed=123`, все признаки независимо равномерные | Эталон шума: с ним сравниваем качество разбиения основного набора |

Центроиды экотипов разведены по **разным** направлениям признакового пространства. Первая
версия задавала одинаковый порядок по всем пяти признакам (кишечник < вода < почва) — данные
выродились в одномерный градиент, где «вода» оказалась буквально серединой, и силуэт
справедливо находил два кластера вместо трёх.

Расстояние между центроидами подобрано так, чтобы задача не решалась тривиально: при разведении
в 1.5 раза сильнее экотипы восстанавливаются идеально на любом seed. На принятых параметрах
восстановление в среднем ARI ≈ 0.75 и идеально лишь в 5 прогонах из 30.

Seed основного набора выбран перебором ([seed_sweep.py](../data/seed_sweep.py)) среди тех, где
силуэт определяет k=3, а ARI попадает в 0.65–0.93 — то есть один-два штамма относятся не к
своему экотипу, и это предмет интерпретации. Идеальное восстановление для учебного разбора
бесполезно: обсуждать нечего. Условию отвечают 58 из первых 200 seed'ов, принят seed 11
(k=3, силуэт 0.494, ARI 0.70 — два штамма не в своём экотипе).

Экотипы задают структуру, но метки экотипов в кластеризацию не подаются — только как скрытая
истина для проверки, насколько найденное разбиение их воспроизводит.

Оба CSV коммитим в репозиторий: результат должен воспроизводиться без повторного запуска генератора.

## Этапы

**1. Загрузка и валидация.** 20 строк, уникальные `strain_id`, отсутствие пропусков,
`has_plasmid` только 0/1, `source` только из трёх допустимых значений, количественные признаки
в физически осмысленных диапазонах. Нарушение схемы — явная ошибка, а не тихое продолжение.

**2. Предобработка.** Стандартизация пяти количественных признаков: вычесть среднее, разделить
на стандартное отклонение по выборке (знаменатель `n`, как в `StandardScaler`). Источник
выделения — one-hot в три колонки, **без** отбрасывания первой: евклидово расстояние по полной
кодировке даёт одинаковый результат для любой пары различных категорий, а усечённая кодировка
ломает эту симметрию.

**3. Матрица расстояний — ядро задачи.** Три компоненты считаются отдельно:

| Компонента | Метрика | Область значений | Вес |
|---|---|---|---|
| 5 количественных признаков | Евклидово по стандартизованным | от 0 до ~6 | 0.6 |
| Наличие плазмиды | Хэмминга по одному признаку | 0 или 1 | 0.2 |
| Источник выделения | Евклидово по one-hot | 0 или √2 | 0.2 |

Каждую матрицу делим на её собственный максимум, затем складываем с весами. Деление защищено
от нулевого максимума — он возможен, если признак на данном наборе оказался константой.
Результат: симметричная матрица 20×20 с нулевой диагональю и значениями в \[0, 1].

Два вырожденных признака из трёх дают всего два уникальных расстояния каждый. Это значит, что
40% итогового расстояния — ступенчатая функция, и количественная компонента остаётся
единственным источником непрерывной геометрии. Ожидаемое следствие: кластеры будут тяготеть
к разбиению по комбинации «источник × плазмида». Проверяем это явно, сравнивая найденные
кластеры с этими двумя признаками.

**4. Кластеризация и подбор числа кластеров.** Иерархическая кластеризация методом Уорда по
сжатой форме матрицы. Для каждого k от 2 до 10 — разрез дендрограммы и индекс силуэта,
посчитанный **на той же** матрице расстояний. Оптимальное k — по максимуму силуэта.

Выводим всю таблицу `k → силуэт`, а не только победителя: на 20 объектах разница между
соседними k часто лежит в пределах шума, и видеть профиль важнее, чем одно число. При k=10
средний кластер — 2 объекта, силуэт там теряет смысл; отмечаем это в интерпретации.

Параллельно — тот же подбор на average linkage. Совпадение разбиений подтверждает устойчивость
результата, расхождение — измеряет цену допущения о метрике Уорда.

**5. Профили кластеров.** Для каждого кластера: размер, средние значения пяти количественных
признаков **в исходных единицах** (не в стандартизованных — читать проценты GC и мегабазы
осмысленнее, чем z-оценки), мода источника выделения с указанием, насколько она доминирует,
доля штаммов с плазмидой.

**6. Визуализация.** Три представления, каждое отвечает на свой вопрос:

| Что строим | Какой вопрос закрывает |
|---|---|
| Дендрограмма с линией разреза | Как устроена иерархия и насколько произволен выбранный разрез |
| Главные компоненты (PCA) по признакам, окраска по кластерам | Требование задания; подписываем долю объяснённой дисперсии |
| Многомерное шкалирование (MDS) по нашей матрице | Честная проекция именно того расстояния, по которому кластеризовали |

PCA работает с признаками, а кластеры построены по взвешенной матрице — поэтому на PCA-картинке
кластеры могут выглядеть перемешанными даже при корректной кластеризации. MDS этого расхождения
не даёт. Координаты PCA выгружаем в CSV, как требует задание.

Текстовое описание структуры кластеров печатается всегда — как фолбэк на случай недоступности
графики.

**7. Тесты.** Матрица: симметрия, нулевая диагональ, значения в \[0, 1], корректная реакция на
константный признак. Расстояния: ручной расчёт на трёх штаммах, сверенный с кодом. Веса: сумма
равна 1, подмена весов меняет результат предсказуемо. Пайплайн: прогон на обоих наборах без
падений, воспроизводимость при повторном запуске.

## Максимума силуэта недостаточно

Замер на готовых наборах (обе таблицы в репозитории, метрика — взвешенная смесь из п.3):

| Набор | Оптимальное k | Силуэт | Второе место |
|---|---|---|---|
| Основной, структура заложена | 3 | 0.494 | k=5 — 0.492 |
| Контрольный, чистый шум | 5 | 0.402 | k=7 — 0.386 |

Два факта, которые это вскрывает:

**Профиль силуэта на основном наборе почти плоский** — 0.490 при k=2, 0.494 при k=3, 0.492 при
k=5. Разрыв между победителем и вторым местом 0.004, на 20 объектах это шум. Подавать argmax как
найденный ответ нельзя: выводим всю таблицу `k → силуэт` и говорим о плато, а не о точке.

**На чистом шуме силуэт даёт 0.402** — всего на 0.09 ниже, чем на данных с реальной структурой.
Критерий «максимум силуэта» сам по себе не отличает структуру от её отсутствия при n=20.

Поэтому в пайплайн добавляется проверка значимости: генерируем ~200 шумовых наборов того же
размера, для каждого считаем максимум силуэта по k, и смотрим, в какой процентиль этого
распределения попадает наш наблюдённый 0.494. Это превращает «силуэт высокий» в проверяемое
утверждение.

## Критерии готовности

- Разбиение основного набора воспроизводит заложенные экотипы — проверяется по
  [скрытой истине](../data/strains_truth.csv) через ARI, цель > 0.7.
- Наблюдённый силуэт лежит выше 95-го процентиля шумового распределения.
- Ward и average дают близкие разбиения — результат не артефакт выбора метода связи.
- Два-три штамма с несовпадающим источником разнесены по кластерам согласно количественным
  признакам, а не категории: проверка, что вес 0.6 действительно перебивает ложную метку.
